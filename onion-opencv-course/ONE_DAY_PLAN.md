# 🧅 ONE-DAY PLAN — SIH26031 Onion Quality Grader

> You have ~24 hours. This plan assumes you **already have** the working code in
> this folder. Your job now = **demo it, explain it, and rehearse it.**

## The honest strategy (read this first)

A hackathon judge in round 1 wants to see: **a working demo + a clear pitch + a
team that knows their own limits.** You do NOT need a perfect app. You need:

1. A live demo that runs on a phone browser (you already have `app.py`).
2. A crisp explanation of the pipeline (you already know it — it's the book).
3. An honest "what a camera can't see" line (impresses judges more than hype).

**DO NOT** try to train a deep model today. The rule-based version + a clean UI
wins more points than a half-trained CNN that crashes on stage.

## Hour-by-hour schedule

### Hours 0–2 — Rehearse the demo (what you're doing right now)
- [ ] Run `python app.py` → open on your phone browser via the preview URL.
- [ ] Upload `images/demo_batch.jpg` → see Grade A / URS / Reject percentages.
- [ ] Upload a **photo you take right now** with 3–4 onions + a ₹10 coin.
- [ ] Run it 5 times until it never crashes.

### Hours 2–5 — Make it yours
- [ ] Change the app title/colors to your team name.
- [ ] Add the **problem statement** text to the report (`report.txt` header).
- [ ] Test edge cases: empty photo, no coin (does it print the warning?), dark background.
- [ ] Take 10 real onion photos with your phone (your "dataset" for the demo).

### Hours 5–8 — Fix the top 3 failure modes (the ones judges will find)
- [ ] **Overlapping onions** → if onions touch, they merge into one blob.
      Quick fix: photograph them spaced apart (recommended). Real fix: watershed
      segmentation (ask AI: "implement watershed segmentation for touching onions").
- [ ] **No coin in photo** → app assumes median=55 mm. Add a UI field "coin diameter (mm)"
      so the user can type 27/23/22 — 10 lines of code.
- [ ] **Beige/colored background** → Otsu breaks. Quick fix: tell users "use a white
      paper background". Better fix: HSV-based background removal.

### Hours 8–12 — Build the "digital quality report" properly
- [ ] The report card image already exists (`batch_output/report_card.jpg`).
- [ ] Add: date/time, batch ID, location, "generated by" line.
- [ ] Optionally save reports to a folder and list past reports in the UI.

### Hours 12–14 — Mobile polish
- [ ] Make the page full-screen, bigger buttons (it's already responsive).
- [ ] Test from an actual phone (use your phone's browser).
- [ ] (Optional) "Add to Home Screen" → the app then *feels* like a native app.
      This satisfies "mobile application" without building Android/iOS.

### Hours 14–16 — Pitch deck (6 slides max)
1. Problem (the disputes + subjectivity — use the PS wording)
2. Solution overview (1 pipeline diagram)
3. Live demo (the app)
4. How it works (features: color/shape/texture/size + grade rules)
5. Honest limitations (surface-only; no internal rot)
6. Roadmap (ML on labeled data → CNN → local-language UI → Hindi/regional)

### Hours 16–20 — Write the 2-minute pitch + rehearse
Pitch skeleton (fill in your own words):
> "Onion grading at procurement centres is subjective and causes disputes. We
> built an AI mobile app that grades a batch from one photo. It detects each
> onion, classifies damaged/rotten/sprouted/undersized, measures size using a
> coin for scale, and instantly gives Grade A and URS percentages with a digital
> report — removing human bias and improving transparency."
Then show the live demo. End with the limitations line.

### Hours 20–24 — Sleep 2–3 hours + final dry run
- [ ] Full run-through: intro → demo → questions.
- [ ] Charge phone + laptop. Have a backup: if Wi-Fi dies, show the saved
      `batch_output/annotated.jpg` and `report_card.jpg` offline.

## Honest limitations (say these out loud — it wins trust)
1. Grades **visible surface quality only** — cannot detect internal rot.
2. Size is estimated from a reference coin (mm accuracy depends on camera angle).
3. Rule-based now; accuracy improves with a labeled dataset + ML/CNN (roadmap).
4. Overlapping onions need spacing (or watershed as next step).
