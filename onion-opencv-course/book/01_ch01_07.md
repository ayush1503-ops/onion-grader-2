# Chapter 2 — What Is an Image? Pixels, Resolution & BGR
> 🎥 **PLAYLIST CONTENT** — Part 1 "Image Basics".

## 1. Learning Objectives
1. Define a pixel. 2. Explain resolution and dimensions. 3. Explain channels and BGR. 4. Inspect an image's shape with NumPy.

## 2. Simple Explanation
A digital image is a **grid of tiny colored squares**. Zoom into any photo far enough and you'll see those squares — **pixels**. A 1920×1080 photo is a grid 1920 squares wide and 1080 squares tall: that's **resolution**. Each pixel stores a color as three numbers: how much Blue, Green, Red (OpenCV's order: **BGR**).

## 3. Technical Explanation
- A grayscale image is a 2-D array: `img[y, x]` = brightness (0 = black, 255 = white).
- A color image is a 3-D array: `img[y, x, c]`, where channel `c` is 0=Blue, 1=Green, 2=Red.
- `img.shape` returns `(height, width, channels)` for color or `(height, width)` for gray.
- Data type is usually `uint8` = unsigned 8-bit integer, values 0–255 (256 levels = 2⁸).

## 4. Real-World Example
"4K TV" = 3840×2160 pixels. "8 megapixel camera" ≈ a grid of 8 million pixels. More pixels = more detail, bigger file, slower processing.

## 5. OpenCV Example
```python
import cv2
img = cv2.imread("onion.jpg")
print(img.shape)        # e.g. (800, 640, 3) -> 800 rows, 640 cols, 3 channels
print(img.dtype)        # uint8
print(img[100, 100])    # BGR values of the pixel at row 100, col 100
```

## 6. 🧅 Onion Project Example
A 1000×1000 onion photo is a grid of **one million** pixels. The analyzer only ever does math on these numbers — that's why "quality" must be *visible in the pixels*.

## 7. Practical Code
```python
import cv2, numpy as np
img = cv2.imread("images/demo_good.jpg")
h, w, c = img.shape
print("height", h, "width", w, "channels", c)   # e.g. height 640 width 640 channels 3
print("top-left pixel (BGR):", img[0, 0])        # near-white background -> (255,255,255)
```

## 8. Expected Output
```text
height 640 width 640 channels 3
top-left pixel (BGR): [255 255 255]   (white background)
```

## 9. Visual Explanation
```text
A tiny 4x4 color image:
(0,0) (0,1) (0,2) (0,3)      each cell = 1 pixel,
(1,0) (1,1) (1,2) (1,3)      each pixel = [B, G, R]
(2,0) (2,1) (2,2) (2,3)      shape = (4, 4, 3)
(3,0) (3,1) (3,2) (3,3)
```
**See → Do → Why → Result:** see a grid → read `img.shape` → you must know height/width to loop, slice, resize → you can now talk about any image numerically.

## 10. Common Mistakes
- Reading `shape` as (width, height) — it's **(height, width)**.
- Forgetting the 3rd number exists (channels) and indexing `img[y, x]` on a color image — that returns a 3-element array, not one number.
- Assuming values are RGB — they're BGR.

## 11. Practice Task

## 12. Questions + Solutions
- **Q:** What is a pixel? **A:** the smallest element of an image — one colored square.
- **Q:** What does `(600, 400, 3)` mean? **A:** 600 rows, 400 columns, 3 color channels.
- **Q:** Why `uint8`? **A:** each channel is one byte, values 0–255.
- **Q:** What's BGR? **A:** OpenCV's channel order: Blue, Green, Red.

# Chapter 3 — Reading an Image
> 🎥 **PLAYLIST CONTENT** — Part 2 "Reading an Image".

## 1. Learning Objectives
1. Load images with `cv2.imread`. 2. Display with `imshow` + `waitKey`. 3. Handle "image not found" (`None`). 4. Know the read flags.

## 2. Simple Explanation
`cv2.imread(path)` opens a file and hands you the image as a NumPy array. `cv2.imshow(title, img)` puts it in a window. `cv2.waitKey(0)` keeps the window open. `cv2.destroyAllWindows()` cleans up.

## 3. Technical Explanation
- `cv2.imread(path, flags)` — flags: `cv2.IMREAD_COLOR` (default, 3-channel BGR), `cv2.IMREAD_GRAYSCALE` (0), `cv2.IMREAD_UNCHANGED` (-1, keeps alpha).
- Returns `None` if the file can't be read (wrong path, unsupported format) — **always check for `None`**.
- `cv2.waitKey(0)` waits indefinitely for a key; `waitKey(n)` waits n milliseconds.

## 4. Real-World Example
Every app that processes a photo starts with "load the file into memory."

## 5. OpenCV Example
```python
import cv2
img = cv2.imread("images/demo_good.jpg")      # color (BGR)
gray = cv2.imread("images/demo_good.jpg", cv2.IMREAD_GRAYSCALE)
assert img is not None, "image not found!"
cv2.imshow("Color", img)
cv2.imshow("Gray", gray)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

## 6. 🧅 Onion Project Example
Your analyzer's very first line is `img = cv2.imread(...)`. If the user uploads a photo to a wrong path, `img` is `None` and everything downstream crashes — so you check for `None` and show a friendly error.

## 7. Practical Code
```python
import cv2, os
path = "images/demo_good.jpg"
img = cv2.imread(path)
if img is None:
    print("ERROR: could not read", path, "- does the file exist?")
else:
    print("Loaded:", img.shape)
```

# Chapter 4 — Converting to Grayscale
> 🎥 **PLAYLIST CONTENT** — Part 3 "Converting RGB image to Grayscale".

## 1. Learning Objectives
1. Convert BGR → gray with `cvtColor`. 2. Understand the luminance formula. 3. Explain why grayscale is useful.

## 2. Simple Explanation
Grayscale keeps only **brightness** and throws away color: one number per pixel instead of three. The image becomes smaller (1 channel), simpler, and many algorithms (thresholding, edges) work on gray first.

## 3. Technical Explanation
`cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)` applies a weighted sum of the channels:
`Y = 0.299·R + 0.587·G + 0.114·B`
Green is weighted most because human eyes are most sensitive to green.

## 4. Real-World Example
Old black-and-white TV, or printing in grayscale to save ink — same idea: only brightness matters.

## 5. OpenCV Example
```python
import cv2
img = cv2.imread("images/demo_good.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
print(img.shape, "->", gray.shape)   # (640,640,3) -> (640,640)
```

## 6. 🧅 Onion Project Example
We threshold on the grayscale image to separate the onion from the background, and we use it for dark-spot detection — fewer channels = fewer surprises.

## 7. Practical Code + 8. Expected Output
```python
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
print(gray[0, 0], gray[320, 320])   # background pixel vs onion pixel
```
Output (real run): background ≈ `255`, onion ≈ `200` — the onion is darker.

## 10. Common Mistakes
- Using `COLOR_GRAY2BGR` to convert gray → color and expecting color to come back (it stays gray, just 3 identical channels).
- Calling `cvtColor` on an already-gray image.

# Chapter 5 — Playing with Color Channels
> 🎥 **PLAYLIST CONTENT** — Part 4 "Playing with RGB Color Channels".

## 1. Learning Objectives
1. Split and merge channels. 2. Visualize single channels. 3. Use a channel to highlight defects.

## 2. Simple Explanation
A color image is three stacked layers: Blue, Green, Red. `cv2.split` gives you the three layers separately; `cv2.merge` puts them back. Each layer alone looks like a grayscale image of "how much of that color" is present.

## 3. Technical Explanation
```python
b, g, r = cv2.split(img)      # three 2-D arrays
merged = cv2.merge([b, g, r])
```
You can also zero out channels to make a "blue-only" image: `img[:, :, 0]` keeps blue.

## 4. Real-World Example
NASA satellite images use many channels (including infrared). Analyzing one channel can reveal things invisible in the full color image.

## 5. OpenCV Example
```python
import cv2, numpy as np
img = cv2.imread("images/demo_good.jpg")
b, g, r = cv2.split(img)
print("Blue channel mean:", b.mean(), "Red mean:", r.mean())
only_red = img.copy(); only_red[:, :, 0] = 0; only_red[:, :, 1] = 0   # keep only R
cv2.imshow("Only red channel", only_red); cv2.waitKey(0)
```

## 6. 🧅 Onion Project Example
Dark/rotten areas often look **reddish-brown** — so the **red channel** can exaggerate defect regions and help find them. This is a cheap, real trick we'll use in feature extraction.

## 7. Practical Code + 8. Expected Output
```python
r = img[:, :, 2]
print("red channel mean:", round(float(r.mean()), 1))
```
Real run on the demo good onion: red mean ≈ **157** (on a white background the red channel is high).

## 9. Visual Explanation
```text
BGR image  →  split  →   [ Blue layer ]   (bright where the image is blue)
                         [ Green layer ]  (bright where green)
                         [ Red layer ]    (bright where red)
```
**See → Do → Why → Result:** see three gray layers → `cv2.split` → isolating channels lets you build feature masks → e.g. "red channel > threshold" = possible brown/rot pixels.

## 10. Common Mistakes
- Confusing index order: channel 0 is **B**, 2 is **R**.
- `split` is slow for huge images; usually you only need one channel: `img[:, :, 2]`.

## 11. Practice Task

## 12. Questions + Solutions

- **Q:** Why is the red channel useful for onions? **A:** brown/rot regions are reddish, so they stand out in the red channel.

# Chapter 6 — Resizing an Image
> 🎥 **PLAYLIST CONTENT** — Part 5 "Image Resizing".

## 1. Learning Objectives
1. Resize with `cv2.resize`. 2. Know interpolation flags. 3. Preserve aspect ratio. 4. Standardize image sizes.

## 2. Simple Explanation
Resizing changes the grid's dimensions: 1000×1000 → 300×300. You must choose how to *guess* new pixels — that choice is **interpolation**.

## 3. Technical Explanation
`cv2.resize(img, (width, height), interpolation=...)`
- `INTER_AREA` — best for **shrinking** (averages pixels, no aliasing).
- `INTER_LINEAR` — default, okay for enlarging.
- `INTER_CUBIC` — slower, better for enlarging.
To keep the shape, scale width and height by the same factor.

## 4. Real-World Example
Instagram thumbnails, video streaming (multiple resolutions), and ML models all demand fixed-size inputs.

## 5. OpenCV Example
```python
import cv2
img = cv2.imread("images/demo_good.jpg")
small = cv2.resize(img, (320, 320), interpolation=cv2.INTER_AREA)
big = cv2.resize(small, (960, 960), interpolation=cv2.INTER_CUBIC)
print(small.shape, big.shape)
```

## 6. 🧅 Onion Project Example
A classifier expects **every** image to be the same size. We resize every onion photo to 640×640 before analysis — this standardization is mandatory, not optional.

## 7. Practical Code (aspect ratio preserved)
```python
h, w = img.shape[:2]
scale = 640 / w
img2 = cv2.resize(img, (640, int(h * scale)), interpolation=cv2.INTER_AREA)
```

## 8. Expected Output
`(640, 640, 3)` for a square input; otherwise width 640 with proportional height.

## 9. Visual Explanation
```text
original 640x640 ──INTER_AREA──▶ 320x320   (pixels averaged together)
320x320 ──INTER_CUBIC──▶ 960x960           (pixels invented, slightly blurry)
```
**See → Do → Why → Result:** shrinking averages pixels (smooth); enlarging invents pixels (blurry) → pick the right flag → no jagged edges in your dataset.

## 10. Common Mistakes
- Passing `(height, width)` instead of `(width, height)` to `resize`.
- Using `INTER_LINEAR` to shrink large images → jagged lines (use `INTER_AREA`).
- Forgetting to resize before feeding a model → shape mismatch error.

## 11. Practice Task

## 12. Questions + Solutions
- **Q:** Which flag shrinks best? **A:** `INTER_AREA`.
- **Q:** What does `cv2.resize(img, (w, h))` take — (w,h) or (h,w)? **A:** (width, height).

## 1. Learning Objectives
1. Flip horizontally/vertically/both with `cv2.flip`. 2. Use flipping for **data augmentation**.

## 2. Simple Explanation
Flipping is mirroring the image: left-right (like a mirror), top-bottom, or both (180° rotation).

## 3. Technical Explanation
`cv2.flip(img, flipCode)` — `1` = horizontal, `0` = vertical, `-1` = both.

## 4. Real-World Example
Selfie cameras mirror your face by default; flipping is also the cheapest way to double a training dataset.

## 5. OpenCV Example
```python
import cv2
img = cv2.imread("images/demo_good.jpg")
h = cv2.flip(img, 1)   # horizontal (mirror)
v = cv2.flip(img, 0)   # vertical
b = cv2.flip(img, -1)  # both (180°)
```

## 6. 🧅 Onion Project Example
From **one** onion photo you get **two** training images (original + flipped). An onion rotated 180° is still the same onion — flipping is safe augmentation that doubles your dataset for free.

## 7. Practical Code + 8. Expected Output
```python
augmented = cv2.flip(img, 1)
cv2.imwrite("images/onion_flipped.jpg", augmented)
```
Output: a saved mirror image, same dimensions.

## 9. Visual Explanation
```text
flipCode 1:  A → A   (mirror left-right)
flipCode 0:  A ↔ V   (mirror top-bottom)
flipCode -1: A ↔ V + left-right  (180°)
```
**See → Do → Why → Result:** flip with the right code → more varied data → a model that isn't fooled by left/right orientation.

## 10. Common Mistakes
- Confusing `1` and `0` (horizontal vs vertical).
- Flipping text/numbers in photos when orientation matters (not an issue for onions).

## 11. Practice Task
Create all three flips and save them with clear names.

## 12. Questions + Solutions
- **Q:** `cv2.flip(img, -1)` does what? **A:** flips both axes (180°).
- **Q:** Why is flipping useful for the dataset? **A:** doubles data with zero new photos; valid because an onion's orientation doesn't change its quality.
