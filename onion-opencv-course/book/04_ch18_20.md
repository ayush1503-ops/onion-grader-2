# Chapter 18 — Contours, Bounding Boxes & Masks
> ➕ **ADDITIONAL PROJECT KNOWLEDGE**.

## 1. Learning Objectives
1. Find contours with `cv2.findContours`. 2. Pick the largest contour. 3. Draw bounding boxes. 4. Build and apply a mask.

## 2. Simple Explanation
A **contour** is the outline of a white blob in a binary image. From the contour you can get the **bounding box** (the smallest rectangle around the object) and a **mask** (an image where "object = 255, everything else = 0"). The mask is how you *cut the onion out* of the photo.

## 3. Technical Explanation
```python
contours, _ = cv2.findContours(binary, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
largest = max(contours, key=cv2.contourArea)
x, y, w, h = cv2.boundingRect(largest)
mask = np.zeros_like(gray)
cv2.drawContours(mask, [largest], -1, 255, -1)      # fill the contour
onion_only = cv2.bitwise_and(img, img, mask=mask)   # keep only onion pixels
```
- `RETR_EXTERNAL` = only outer contours (ignore holes).
- `bitwise_and` applies the mask: pixels where mask=0 become black.

Counting coins, tracking objects in videos, measuring product size on conveyor belts.

# Chapter 19 — Histograms & Feature Extraction
> ➕ **ADDITIONAL PROJECT KNOWLEDGE**.

## 1. Learning Objectives
1. Read a histogram. 2. Compute color, shape and texture **features**. 3. Understand why features are the bridge to ML.

## 2. Simple Explanation
A **histogram** counts how many pixels have each brightness/color — it's the "summary statistics" of an image. A **feature** is one number that summarizes an aspect of the onion: area, roundness, mean color, how much is brown. A handful of features turn "a whole image" into "a short list of numbers" a human (or a model) can reason about.

## 3. Technical Explanation
```python
hist = cv2.calcHist([gray], [0], None, [256], [0, 256])
```
Features we use (all on masked onion pixels):
- **Shape**: area (`countNonZero`), perimeter (`arcLength`), **circularity** = 4πA/P² (1.0 = perfect circle), **aspect ratio** = h/w, **extent** = A/(w·h).
- **Color**: mean HSV, standard deviation of gray (**texture** proxy — rough/rotten skin has higher std).
- **Defects**: `dark_ratio` = fraction of very dark pixels; `brown_ratio` = fraction of brown (HSV-range) pixels.

## 4. Real-World Example
Photo apps' "brightness" slider is histogram shifting; medical labs measure cell roundness to flag abnormal cells.

## 5. OpenCV Example
```python
import cv2
gray = cv2.imread("images/demo_good.jpg", cv2.IMREAD_GRAYSCALE)
hist = cv2.calcHist([gray], [0], None, [256], [0, 256])
print("dark pixels (<70):", (gray < 70).mean().round(4))
```

Our analyzer computes exactly these features. A rotten onion has a high `dark_ratio` and `brown_ratio`; a healthy one is rounder (circularity ≈ 0.75) with a low defect ratio.

# Chapter 20 — 🛠 Mini-Project: The Rule-Based Onion Analyzer v1
> ➕ **ADDITIONAL PROJECT KNOWLEDGE** — this is your **first working prototype**.

## 1. Learning Objectives
1. Assemble the full pipeline into one program. 2. Use simple rules over features. 3. Output a labeled, boxed result.

## 2. Simple Explanation
Now we glue Chapters 2–19 into one pipeline:

```text
read → resize → grayscale → blur → Otsu threshold → morphology
     → largest contour → mask → features → rules → GOOD/DAMAGED/ROTTEN → annotate
```

If the rules are simple enough, this is **traditional computer vision** — no training, no model, just math you can read.

## 3. Technical Explanation
The pipeline is the real file `src/onion_analyzer.py` (full code in the Appendix). The **rules** are deliberately simple:

```python
def classify(feats):
    dr, br = feats["dark_ratio"], feats["brown_ratio"]
    if dr >= 0.12 or br >= 0.40: return "ROTTEN"
    if dr >= 0.04 or br >= 0.15: return "DAMAGED"
    return "GOOD"
```

> ⚠️ **These thresholds are DEMO values tuned to my three demo images.** They are *not* scientific. Chapter 24 shows how to pick real thresholds from a labeled dataset.

## 4. Real-World Example
Factory vision systems started exactly like this — a few hand-tuned rules — before ML took over.
